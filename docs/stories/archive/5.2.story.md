# Story 5.2 Fix Read-Mode Overlay Interaction & Send Detection

## Story
As a TeX for Gmail user
I want to interact with rendered equations in read mode and have reliable send detection
So that I can copy LaTeX source and ensure all LaTeX patterns are rendered before sending

## Status
Proposed

## Epic
Epic 5: Critical Bug Fixes & Stability

## Priority
P1 - Major

## Description
Fix the read-mode overlay that blocks pointer events, preventing Copy LaTeX functionality. Expand send detection to include all LaTeX delimiter patterns and improve send button detection to be locale/DOM-change resilient. Ensure toggle state is properly restored after programmatic send.

## Technical Context
The CSS `pointer-events: none` on overlay parents prevents child interaction. Send detection only checks for `$...$` and `$$...$$`, missing other valid LaTeX delimiters. Button detection relies on brittle tooltip/text matching.

## Acceptance Criteria
1. Read-mode overlay allows pointer events on math elements:
   - Copy LaTeX button responds to hover and click
   - Context menu (Shift+F10) works on equations
   - Original text remains visually hidden but not blocking
2. Send detection expanded to include all LaTeX patterns:
   - `$...$` and `$$...$$` (existing)
   - `\(...\)` and `\[...\]` (new)
   - Optional: theorem environment blocks
3. Send button detection uses structural DOM navigation instead of text/tooltip matching
4. Original toggle state restored after programmatic send completion
5. Send dialog appears consistently for all LaTeX pattern types per user settings

## Implementation Details
- Refactor overlay CSS to allow events on content layer while keeping original text hidden
- Update send detection regex to include all delimiter patterns
- Implement structural send button detection (compose container → send control)
- Store original toggle state before send, restore after completion
- Add proper cleanup of temporary observers after send

## Test Plan
1. Test Copy LaTeX in read mode:

2. Test send detection with various patterns:
   - `$x^2$` (inline math)
   - `$$\int_0^1$$` (display math)
   - `\(a + b\)` (LaTeX inline)
   - `\[x = y\]` (LaTeX display)
3. Test send in different Gmail locales/themes
4. Verify toggle state restoration after send
5. Test with "Always render", "Never render", and "Ask" settings
